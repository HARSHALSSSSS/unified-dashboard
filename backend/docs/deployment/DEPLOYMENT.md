# Deployment

## Artefacts

One Dockerfile (`infrastructure/docker/Dockerfile`) builds every process: `--build-arg APP=api|worker|scheduler|webhook-worker`.

- **Bundle**: `tsup` bundles our workspace packages; third-party packages stay external and are listed with **exact installed versions** in `dist/package.json` (generated by `scripts/tsup-app.mjs`). Native modules (argon2) and packages that read files at runtime (bullmq) therefore work.
- **Runtime image**: `node:22-alpine`, `npm install --omit=dev` from that file, **non-root**, `HEALTHCHECK` on `/health/live`. Verified locally by installing the generated `dist/package.json` into an empty directory and booting the bundle.
- **`migrate` target**: full workspace image that runs `db:migrate` then `db:seed` with the owner role.
- Image tags: git SHA + semver; deploy by immutable tag.

## Environments

| | local | staging | production |
|---|---|---|---|
| Orchestration | docker compose | Kubernetes / ECS | Kubernetes / ECS |
| PostgreSQL | container | managed (RDS/Cloud SQL), small | managed, Multi-AZ, PITR, PgBouncer |
| Redis | container | managed | managed, replicas, `maxmemory-policy noeviction`, AOF |
| Object storage | MinIO | S3 | S3 + lifecycle + private bucket |
| Config/secrets | `.env` | secret manager | secret manager |
| Swagger | on | on | off |

## Release flow

```
PR → CI: typecheck · lint · check:modules · tests · OpenAPI contract · build · docker build
main → build+push images (tag = sha)
deploy: 1) run `migrate` job (owner role)   2) roll workers + api (maxUnavailable 0)   3) smoke test (E2E_BASE_URL) 
rollback: redeploy previous image tag. Migrations are expand/contract so the previous version still works against the new schema.
```

Order matters: **migrate first, then app**; the new schema must be backward compatible with the *running* version (additive changes; destructive ones in a later release).

## Process topology and sizing (starting point)

| Process | Replicas | Scale on | Notes |
|---|---|---|---|
| api | ≥ 2 | CPU / RPS | stateless, `TRUST_PROXY=1` (hop count), PDB `minAvailable: 1`, preStop sleep for LB drain |
| worker | ≥ 2 | queue depth (KEDA) | split pools with `WORKER_QUEUES` (e.g. dedicated `marketplacePush`) |
| webhook-worker | ≥ 2 | queue depth | isolates webhook storms |
| scheduler | 1–2 | n/a | idempotent; replicas are safe |

Reference manifests: `infrastructure/k8s/base` (Deployment, Service, HPA, PDB, probes, hardened securityContext). Probes: startup/liveness `/health/live`, readiness `/health/ready`.

## Graceful shutdown

SIGTERM → stop accepting HTTP (idle connections closed) → workers finish in-flight jobs (`terminationGracePeriodSeconds: 60`) → close queues → DB pool → Redis → flush traces. Hooks run in reverse registration order, once.

## Database operations

- Run migrations with `DATABASE_MIGRATION_URL` (owner). App uses `DATABASE_URL` (`oms_app`, `NOBYPASSRLS`).
- Behind PgBouncer use **transaction pooling** (compatible with transaction-local tenant settings).
- Provision the two roles via IaC using `infrastructure/postgres/init.sql` as the reference.
- Backups: PITR + daily snapshot; restore drill quarterly.

## Secrets and config

Inject through the platform (External Secrets/CSI/Parameter Store). Required in production: `DATABASE_URL`, `DATABASE_MIGRATION_URL` (migrate job only), `REDIS_URL`, `JWT_ACCESS_SECRET`, `ENCRYPTION_KEYS`, storage settings, `PUBLIC_BASE_URL`, `CORS_ORIGINS`. Validation at boot rejects missing/weak values.

## Pre-production checklist

See the operational checklist in [SECURITY](../security/SECURITY.md#operational-checklist-before-production) plus: alerts wired (`infrastructure/observability/alerts.yml`), dashboards for RED + queues, log retention, Redis `noeviction`, load test of `/api/v1/*` and queue throughput, runbooks for "marketplace down", "queue backlog", "DB failover".
